# PCWork Mobile v62 — контролен списък

Легенда: **Включено в изходния код** означава, че функционалността присъства в проекта; **Нужна настройка/проверка** означава, че трябва да бъде конфигурирана на WordPress/Firebase или потвърдена от GitHub Actions/реално устройство.

## A. Нови промени във v62
- [x] Версия `0.62.0+62` и Android application ID `com.pcworkbg.pcwork_mobile` е запазен.
- [x] Редакция на профила с автоматично записване след кратко изчакване.
- [x] Индикатор за запис, съобщение за грешка и повторен опит при неуспешно записване.
- [x] Регистрационният имейл е заключен в приложението; API не приема промяна на WordPress email.
- [x] Име, телефон, billing и отделен shipping адрес се записват към WordPress/WooCommerce.
- [x] Бутонът за презареждане е преименуван на „Презареди данните от сървъра“ и действително извиква `auth.me()`.
- [x] В горната лента е премахнато превключването на език; глобусът е оставен като икона.
- [x] Добавен е бутон за повторно активиране/настройване на push известията от профила.
- [x] Отказът „Не сега“ за push известията се запомня и не показва диалог при всяко стартиране.
- [x] Добавен е публичен WordPress endpoint `/wp-json/pcwork/v1/app/update` за манифест на актуализациите.
- [x] Добавена е администраторска конфигурация за версия, versionCode, HTTPS APK URL и бележки към версията.
- [x] Приложението показва банер за по-нова версия и отваря HTTPS адреса за изтегляне. Инсталирането изисква стандартно потвърждение от Android.
- [x] Снимката на продукт в количката се визуализира върху прозрачен фон.
- [x] WordPress плъгинът е обновен на `4.3.0`.
- [x] WordPress страницата „Интеграции“ записва настройките автоматично при промяна; оставен е резервен бутон само при изключен JavaScript.
- [x] Android GitHub Actions артефактът е преименуван на `pcwork-android-v62-apks`.
- [x] Добавен е `.gitignore` за keystore, пароли и локални build файлове.

## B. Клиентски профил и магазин — запазени/свързани модули
- [x] Регистрация и вход с еднократен код по имейл.
- [x] Профилът се зарежда от WordPress; email е идентификаторът на профила.
- [x] Checkout използва наличните име, email, телефон и адресни данни от профила.
- [x] Липсващ shipping адрес се попълва първоначално от billing адреса, но може да бъде променен отделно.
- [x] WooCommerce поръчки и клиентски данни се обработват през сървърния API.

- [x] Прием на устройство и създаване на сервизен запис.
- [x] Уникален номер, клиент, устройство, сериен номер, описание на проблема, състояние и комплектовка.
- [x] Сервизни обекти и контрол на достъпа до обектите.

- [x] Промяна на статус и разпределяне към техник.

## D. Известия, Chatway и интеграции — налични модули в проекта
- [x] FCM регистрация след вход и съгласие; повторна регистрация при стартиране/връщане в приложението.
- [x] Обновяване на FCM token чрез `onTokenRefresh`; поддръжка на множество устройства.
- [x] Сървърът изтрива FCM token само при доказан FCM `UNREGISTERED`; временни грешки не водят до изтриване.
- [x] Отделно маркетингово съгласие за „Промоции и новини“ през WordPress REST endpoint.
- [x] Chatway session ticket и Visitor Verification подписване на сървъра; секретът не се изпраща в приложението.
- [x] Google Sheets като огледално копие за справки; WordPress остава основният източник на данни.
- [x] Единен WordPress плъгин обединява Auth Bridge, Repairs API, Admin Integration Settings, WooCommerce и Sheets sync.
